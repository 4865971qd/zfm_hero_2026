# AutoAim 前哨自瞄说明

本文只描述 `autoaim` 项目中的前哨站检测、建模、预测、选板和开火链路。它是纯 C++ 实现，不依赖 ROS2，也不与 `zfm_autoaim` 共享代码。

## 1. 相关源码

| 文件 | 职责 |
|---|---|
| `src/detector.cpp`、`src/classifier.cpp` | 检测灯条、配对装甲板、分类出 `outpost` |
| `src/solver.cpp::solveArmor()` | IPPE PnP、相机/云台/世界坐标变换、装甲板 yaw 解算 |
| `src/tracker.cpp` | 识别前哨模式，向 `OutpostTracker` 输入观测，组装 `Target` |
| `src/target.cpp`、`src/target.hpp` | 圆心、旋转方向、三板高度、相位关联和状态机 |
| `src/solver.cpp::solve()` | 飞行时间预测、选板迟滞、瞄准点和开火建议 |
| `configs/standard.yaml` | 弹速、弹道、前哨开火门控参数 |

## 2. 完整数据流

```text
图像
  -> Detector 检测装甲板并分类为 "outpost"
  -> Solver::solveArmor 计算世界坐标 (x, y, z) 和装甲板 yaw
  -> Tracker 发现 tracked_id == "outpost"
  -> OutpostTracker::addMeasurement(x, y, z, yaw, steady_clock_time)
  -> COLLECTING / CALIBRATING / ACTIVE / STATIC
  -> Tracker 将模型写入 Target
  -> Solver 根据弹丸飞行时间预测三块板的位置
  -> 选板、迟滞切板、弹道补偿
  -> 输出 yaw、pitch、distance、fire_advice
```

进入前哨链路的硬条件是分类结果字符串等于 `outpost`。如果分类结果是 `?`、`base`、数字或其他字符串，程序会进入普通四装甲板 EKF，而不是前哨模型。

## 3. 模型假设和固定常量

当前实现针对 RoboMaster 前哨站的固定运动规律，不是任意三装甲板目标拟合器。

| 常量 | 当前值 | 作用 |
|---|---:|---|
| 物理旋转半径 `fixed_R_` | 0.275 m | 生成预测板位；不再强迫 PnP 观测轨迹按该半径拟合 |
| 固定角速度绝对值 | 2.513 rad/s | 约 2.5 s 转一圈；收集阶段只判断方向 |
| 静止判断起始时间 | 0.4 s | 防止把静止前哨送入旋转模型 |
| 旋转圆拟合最短时间 | 1.20 s | 约覆盖半圈，降低短弧圆拟合多解 |
| 圆拟合最少观测 | 12 次 | 和时间、跨度、残差、稳定性条件同时满足 |
| 圆拟合最小覆盖 | 0.30 m 且 `span/fit_R >= 1.70` | 同时约束绝对位移和相对圆弧覆盖 |
| 自由拟合半径范围 | 0.15~0.36 m | 检查 PnP 轨迹尺度，不替代物理预测半径 |
| 拟合稳定确认 | 0.25 s | 中心变化不超过 0.05 m、半径变化不超过 0.03 m |
| 圆收集最大观测间隔 | 1.0 s | 允许正常板间不可见窗口；超过一次 encounter 丢失时间才重新收集 |
| 静止轨迹跨度阈值 | 0.05 m | 收集窗口任意两次观测的最大平面距离小于该值时进入 STATIC |
| Z 初始间隔 | 0.10 m | 初始化三个高度槽位 |
| Z 标定匹配阈值 | 0.05 m | 判断当前观测是否命中某个高度槽 |
| Z 切板阈值 | 0.06 m | 高度偏离当前最近槽时尝试建立新槽 |
| Z 学习率 | 0.05 | 每块物理板独立低通更新高度 |
| 最大模型相位传播 | 1.0 s | 短时坏观测期间继续按已知转速传播；开火新鲜度仍独立限制为 0.15 s |
| 径向残差阈值 | 0.20 m | 观测半径偏离固定半径过大时判为离群 |
| 最大板关联误差 | 55 deg | ACTIVE 中观测与三块预测板都不接近时判为相位离群 |
| 单次最大相位修正 | 15 deg | 防止一帧 PnP/yaw 噪声直接拖动整个模型 |
| 相位离群持续复位时间 | 0.15 s | 相位关联持续失败后重新收集；径向异常只拒绝当前帧 |

这些值目前写在源码中，不在 YAML 中。如果实车前哨半径、转速或高度结构不同，只调 `outpost_yaw_offset` 无法修正模型本身。

## 4. 状态机

```text
                  旋转目标
COLLECTING ----------------------> CALIBRATING
    |                                  |
    | 位移不足 0.05 m                  | 三个高度槽全部观测到
    v                                  v
 STATIC                              ACTIVE

ACTIVE/CALIBRATING -- 连续相位离群 0.15 s --> COLLECTING
ACTIVE/STATIC -- 无前哨观测超过 1.0 s --> Tracker LOST，销毁模型
```

### 4.1 COLLECTING

输入是当前观测板的世界坐标和 yaw。旧实现使用 `armor - R * normal(yaw)` 逐帧反推圆心；当前实现只把这两个 yaw 候选圆心保留在 debug 日志中，不再参与锁定圆心。

当前实现收集观测板的世界坐标 `(x,y)`，先做代数自由圆初始化，再对 `(cx,cy,R_observed)` 做 Huber 鲁棒几何迭代。`R_observed` 描述 PnP 观测轨迹的尺度；预测三块物理板时仍使用规则半径 `0.275 m`。累计角度变化只用于判断旋转方向；最终角速度固定为 `+2.513` 或 `-2.513 rad/s`。

离开该状态必须同时满足：

1. `0.4 s` 后整段轨迹的最大平面跨度仍小于 `0.05 m` 时判为 STATIC。不能只比较首尾点，因为三板前哨每 `2.5/3≈0.833 s` 会出现一次等价位置重合。
2. 旋转目标的收集时间至少 `1.20 s`、12 次；允许三块板之间正常的短时不可见窗口。
3. 轨迹跨度至少 `0.30 m`，且 `span / fit_R >= 1.70`。
4. 自由半径位于 `[0.15,0.36] m`，残差中位数不大于 `0.06 m`，P80 不大于 `0.10 m`。
5. 第一份合格拟合成为候选；至少 `0.25 s` 后的新拟合与候选中心相差不超过 `0.05 m`、半径相差不超过 `0.03 m`，才进入 CALIBRATING。
6. COLLECTING 中相邻真实观测间隔超过 `1.0 s` 时清空旧轨迹重新收集。`0.15 s` 是短期预测/开火新鲜度尺度，不能用于长期圆收集；否则实车 `0.16~0.26 s` 的正常板间不可见窗口会让模型永远无法完成。

COLLECTING 阶段 `Target.valid=false`，不会进入正常三板求解，也不会开火。

### 4.2 CALIBRATING

进入时把当前真实观测定义为相位槽 0，另外两个相位槽固定为 `+120 deg` 和 `-120 deg`。后续每个观测先按预测相位关联到槽位，再更新该槽自己的高度；不能先按 Z 最近邻猜板号，因为随机旋转方向会让“上中下”和“下中上”的时间顺序相反。

三个相位槽都获得真实高度观测，且排序后相邻高度至少相差 `0.04 m`，才设置 `z_calibrated=true` 并进入 ACTIVE。相位槽与高度的绑定本身就记录了本次攻击窗口里的板序，不再额外把索引强制改成“最高、最低、中间”。

CALIBRATING 阶段仍然 `Target.valid=false`。这是设计行为，不是“识别到了但程序没工作”。

### 4.3 ACTIVE

ACTIVE 中把“同一块板的连续跟踪”和“真实切换到另一块板”分开处理。Z 高度用于确认切板后的物理身份，不能在角度连续时凭单帧最近高度中心改写板号。

处理顺序：

1. 检查观测到圆心的半径是否接近 0.275 m。
2. 分别预测三块板当前相位。
3. 如果当前已跟踪板的相位误差不超过 55 deg，锁定该物理板；即使单帧 Z 更靠近另一个高度中心也不切板。
4. 只有当前板相位误差超过 55 deg、相邻接受观测的装甲板角度发生大跳变、且 Z 明确落入另一个已标定高度槽时，才提交物理板切换。
5. 提交切板时同时更新板号和全局相位，避免把 120 deg 的物理身份变化送入普通相位修正。
6. 切板条件不完整时拒绝该观测，保留长期圆模型和最后一次接受相位；该帧不刷新开火新鲜度。
7. 普通连续观测的单帧相位修正限制在正负 15 deg。
8. 三块高度在进入 ACTIVE 后冻结，本次攻击窗口内不再由单帧观测重写。

最后接受观测后的模型相位最多传播 1.0 秒，避免短时 PnP 拒绝期间预测框冻结；开火仍由 `outpost_max_unseen_time` 的 0.15 秒新鲜度独立限制。模型可以短期继续预测，但过期观测绝不能开火。

ACTIVE 中还维护 `0.35 s` 的连续新鲜观测运动窗。整段平面跨度持续小于 `0.05 m` 才确认停转；观测间隔超过 `0.15 s` 会清空停转确认窗，避免把切板丢帧时间算成静止证据。

### 4.4 STATIC

如果 0.4 秒收集窗口内任意两次观测的最大平面距离仍不足 0.05 m，模型进入 STATIC。静态位置使用 `0.3` 的低通系数更新。

静止判断不能使用 `distance(last, first)`。前哨约 `2.5 s` 转一圈，三块板在几何上等价，因此 Tracker 看到的板位约每 `0.833 s` 回到同一空间位置；此时首尾距离接近零，但中间轨迹跨度约为相邻两板弦长。成功进入 STATIC 的日志会同时输出 `span` 和 `endpoint`，用于区分真实静止与这种周期混叠。

STATIC/STOPPED 只表示当前唯一可见板已经持续静止。Tracker、模型可视化和 Solver 都只使用这一块板，不再生成三个相同 XY 的假装甲板。该模式不要求三高度标定；最近观测仍在 `outpost_max_unseen_time` 内且云台进入射击窗口时，可以直接开火。

## 5. Target 中的前哨数据

ACTIVE 时 `Target.state` 的含义是：

```text
[cx, 0, cy, 0, z_plate0, 0, angle_plate0, omega, R, z_plate1-z_plate0]
```

其他字段：

| 字段 | 含义 |
|---|---|
| `armor_num` | 前哨固定为 3 |
| `d_za` | `z_plate2 - z_plate0` |
| `outpost_angle_offsets[3]` | 三块物理板相对 plate 0 的相位偏移 |
| `outpost_observed_plate` | 最近真实观测关联到的物理板号 |
| `outpost_z_calibrated` | 三个物理高度和板号是否已完成标定 |
| `outpost_last_seen_time` | 最近一次真实 `outpost` 观测时间 |
| `outpost_phase_error` | 最近观测相位与修正模型之间的残差 |

前哨板位置使用：

```text
x_i = cx + R * cos(angle_i)
y_i = cy + R * sin(angle_i)
z_i = z_centers[i]
```

注意这里是圆心加半径方向。普通四装甲板模型使用的是圆心减半径方向，两者符号不能混用。

## 6. 预测和选板

Solver 首先计算：

```text
预测时间 = 当前时间 - Target观测时间 + 弹丸飞行时间 + prediction_delay
```

然后预测目标中心和相位。第一次选板后会用选中板的实际飞行时间再次计算；如果两次预测时间相差超过 3 ms，就重新计算相位和选板。

旋转前哨的火线方向为从目标中心指向枪口：

```text
arrival_fireline = atan2(-predicted_center_y, -predicted_center_x)
arrival_plate_angle[i] = predicted_yaw + angle_offset[i]
```

`predicted_yaw` 已经包含一次 `omega * (flying_time + prediction_delay)`，因此到达火线和装甲板角度不能再次减/加飞行时间。优先选择在弹丸到达时正在接近火线、且到达角差最小的板。切板不是逐帧立即执行，而是带迟滞：

| 条件 | 数值 |
|---|---:|
| 候选板至少优于当前板 | 22 deg |
| 当前板不可继续保持的角差 | 55 deg |
| 强制切板角差 | 88 deg |
| 普通切板确认时间 | 0.090 s |
| 两次切板最小间隔 | 0.160 s |

强制切板用于当前板已经严重离开可用区域的情况。普通切板只有在观测仍新鲜时才累计确认时间。

每个物理板的瞄准 Z 单独平滑：

```text
smooth_z += 0.3 * (measured_z - smooth_z)
```

不能改回单个全局 pitch/Z 平滑器，否则从一块板切到另一块不同高度板时，会把两个物理高度混在一起。

最终物理命中板位和命令瞄准角分别为：

```text
physical_hit_angle = predicted_yaw + selected_angle_offset
command_aim_angle = physical_hit_angle
                    - sign(omega) * outpost_yaw_offset
```

`outpost_yaw_offset` 单位是度，正值表示沿反旋转方向增加命令修正。洋红色 `SEL Pn` 框绘制 `physical_hit_angle` 对应的物理装甲板，不包含该人工修正；控制命令使用 `command_aim_angle`。调参前先确认旋转方向符号和 yaw 坐标约定正确。

## 7. 开火条件

旋转前哨只有同时满足以下条件才会给出 `fire_advice=true`：

1. `outpost_z_calibrated=true`。
2. `outpost_last_seen_time > 0`。
3. 最近真实观测间隔在 `[-0.02, outpost_max_unseen_time]` 内。
4. `abs(outpost_phase_error) <= outpost_max_phase_error`。
5. 选中板位于到达窗口正负 30 deg 内。
6. 选中板正在接近火线，即 `omega * angle_diff < 0`。
7. 当前云台 yaw/pitch 已进入按装甲板物理尺寸换算的射击窗口。

当前默认值：

```yaml
solver:
  outpost_yaw_offset: 0.0
  outpost_max_unseen_time: 0.15
  outpost_max_phase_error: 15.0
```

“画面在跟踪但不开火”时，应按以上七项逐个检查，不要直接放宽射击窗口。

## 8. 丢失和复位

- COLLECTING/CALIBRATING 时 Tracker 保持 DETECTING，目标对 Solver 无效。
- ACTIVE/STATIC 连续两个 Tracker 更新周期后进入 TRACKING。
- TRACKING 中一帧未发现 `outpost` 会进入 TEMP_LOST。
- TEMP_LOST 期间重新观测到 `outpost` 会立即恢复 TRACKING。
- 距离最后真实观测超过 1.0 秒后销毁 `OutpostTracker`，回到 LOST，下次必须重新收集和标定。
- 切回普通目标求解时，Solver 会清空前哨选板索引、候选切板计时和三块板的 Z 平滑状态。

## 9. 最容易出错的地方

### 9.1 分类结果不是 `outpost`

症状：检测框存在，但没有出现前哨状态，整车模型像普通四装甲板目标。

检查：

- `label.txt` 中前哨标签是否准确为小写 `outpost`。
- 模型路径和标签路径是否加载成功。
- 分类置信度是否低于 `classifier_threshold`。
- 前哨站被识别成 LARGE 时会被类型/数字一致性过滤；当前前哨按小装甲板处理。

### 9.2 PnP yaw 方向或坐标系错误

圆心直接由 `x - R*cos(yaw)`、`y - R*sin(yaw)` 得到。yaw 方向错、外参轴错或角点顺序错时，圆心会围着目标漂移，相位关联也会持续失败。

先检查单块板 PnP 和世界坐标，再检查前哨模型。不要用 `outpost_yaw_offset` 掩盖 PnP 符号错误。

### 9.3 最高板一直抖

三块板在逻辑上等价。如果总是同一个画面位置抖，而不是同一个物理板号抖，优先怀疑：

- 图像顶部畸变或角点质量更差。
- 相机曝光导致顶部灯条过曝/断裂。
- PnP 双解在该视角附近切换。
- 世界坐标 Z 对 pitch 更敏感，角点一像素噪声被放大。

如果日志显示物理板号稳定而 Z 抖，问题主要在观测/PnP；如果物理板号反复变化，则检查 Z 槽间距和相位关联。

### 9.4 Z 标定一直不完成

常见原因：

- 只观察到一个或两个高度，第三块板始终被遮挡。
- PnP Z 噪声大于 0.05~0.06 m，观测在槽之间来回跳。
- 相机/云台坐标变换让 Z 随 yaw 周期性漂移。
- 目标实际三块板高度差与初始化的正负 0.1 m 偏差过大。

Z 未标定时不切板、不开火是安全门控，不能通过强行把 `outpost_z_calibrated` 设为 true 绕过。

### 9.5 相位框飞走

检查：

- 时间戳必须来自同一个单调递增的 `steady_clock` 秒值。
- 弹速单位必须是 m/s，不能把 2200 直接当成 m/s。
- 固定角速度符号是否与画面旋转方向一致。
- `outpost_phase_error` 是否频繁接近 55 deg 关联上限。
- 最近观测是否已经超过 0.15 秒；模型只允许有限外推。

### 9.6 切板瞬间 yaw/pitch 跳变

- 确认高度和相位偏移是成对重映射的。
- 确认没有把三块板共用一个 Z 平滑状态。
- `[IDENTITY_LOCK]` 表示 Z 最近槽与当前板不同，但当前板角度仍连续，因此正确保持原板号。
- 检查 debug 日志中的 `[SWITCH_COMMIT]`：必须同时具有当前板大相位误差、大角度跳变和可信的新板 Z；角度连续时不应提交切板。
- `[SWITCH_WAIT]` 表示切板身份暂时不完整，该观测不会刷新预测/开火新鲜度，也不会重建圆模型。
- 不要删除 22/55/88 deg 的切板迟滞和 0.09/0.16 s 时间限制。
- 检查 `aim_idx_` 是否只在前哨模式内保留，离开前哨后必须复位。

### 9.7 一直不开火

依次检查：

1. 是否 ACTIVE，而不是 COLLECTING/CALIBRATING/STATIC。
2. `outpost_z_calibrated` 是否为 true。
3. `outpost_last_seen_time` 是否新鲜。
4. `outpost_phase_error` 是否小于配置阈值。
5. 选中板是否接近火线并且正在接近。
6. 云台是否真正进入射击窗口。
7. 上层是否实际使用 `fire_advice`，以及下位机是否允许开火。

### 9.8 调整 `outpost_yaw_offset` 后更差

该参数只补偿固定方向偏差，不能修正错误弹速、错误外参、错误旋转方向或错误时间戳。调参应从 `0` 开始，小步调整，并分别测试正反转。

### 9.9 低帧率和断流

模型收集、相位离群复位、切板确认和开火新鲜度使用秒，不使用累计帧数。低帧率会减少可用观测，但不会把“15 帧”误解释成不同物理时间。

Tracker 从 ACTIVE/STATIC 到 TRACKING 仍有两个更新周期的交接确认，但真正的建模完成和开火门控由状态、时间和观测新鲜度决定。

### 9.10 修改固定常量时只改了一个项目

`autoaim` 和 `zfm_autoaim` 不共享源码。修改半径、角速度、Z 阈值、相位阈值或切板迟滞时，必须分别修改并分别验证两个项目，不能假设另一个项目会自动同步。

## 10. 推荐验证顺序

1. **只看检测**：确认每次出现的装甲板都分类为 `outpost`，角点和 PnP 稳定。
2. **只看建模**：禁止开火，观察 COLLECTING、CALIBRATING、ACTIVE 状态切换。
3. **检查圆心**：圆心不应随装甲板旋转明显画圆。
4. **检查板号**：三块物理板号应连续稳定，不应在最高板附近频繁互换。
5. **检查 Z**：分别观察三块板的高度趋势，不能只看合成 pitch。
6. **检查预测**：预测板应沿正确方向提前，断流时最多外推 0.15 秒。
7. **检查选板**：切换前应有迟滞，切换后不应立即切回。
8. **最后检查开火**：确认新鲜度、相位、火线窗口和云台窗口全部通过。

调试时一次只改一个参数，并保留对应日志和视频。先验证模型，再调弹道和开火窗口。

## 11. 2026-07-19 仿真验证修正

以下两项属于实车算法修正，已在 `autoaim_1` 的 Gestalt 仿真链路中复现并验证：

1. **异常观测必须由连续的真实测量累计**：`outlier_start_t_` 不能跨越无测量时段继续计时。若新测量与上一测量的间隔超过 `max_outlier_duration_`，先清除旧异常段；重捕获后的第一个坏测量只会开始新的异常段，不会借用断流时间立即重置模型。普通目标丢失仍由 Tracker 的 unseen/lost 超时独立处理。
2. **切板提交必须同时满足观测新鲜和相位有效**：即使当前板超过 88 度强制切板阈值，只要 `abs(outpost_phase_error) > outpost_max_phase_error`，也不得改变 `aim_idx_`。坏相位帧可以记录候选板，但会重启确认计时；相位恢复后再按强制切板或 0.09/0.16 秒迟滞提交。

仿真证据：坏相位 `29~38 deg` 时多次候选切板均被拦截；真正的三次切板相位分别约为 `1.7 deg`、`2.6 deg` 和 `0 deg`。一次异常测量后经历长断流并再次异常重捕获，模型保持 `ACTIVE`，下一帧正常恢复。

最高板持续 pitch 抖动没有归因到算法。仿真中最高板求解 pitch 范围为 `14.30~14.39 deg`，死区后的命令固定为 `14.32 deg`；游戏云台反馈相对发送值平均低约 `1.62 deg`，波动范围明显更大。这是 Gestalt 云台执行/俯仰能力问题，不能据此给实车算法增加 pitch 平滑或高度补偿。

## 12. 真实选板可视化

`show_selected_prediction`/选中板可视化现在直接使用 Solver 本次求解保存的 `selectedArmorPosition()` 和 `selectedArmorYaw()`，不再使用进入前哨专用超前求解之前的初始候选板。

前哨链路中的洋红色选中框按以下顺序产生：

1. 根据观测时间、飞行时间和预测延迟外推目标中心与相位。
2. `selectBestArmor()` 计算候选板，`aim_idx_` 按 22/55/88 度与 0.09/0.16 秒迟滞决定是否真正切板。
3. 使用最终 `aim_idx_`、板高和相位超前生成 `aim_point`/`aim_angle`。
4. Solver 将这个最终物理板位保存为选中板，界面再通过真实相机模型重投影成洋红色框。

因此洋红色框就是算法本次选择的装甲板在预计弹丸到达时刻的物理位置。它不是从最终 yaw/pitch 命令反算出来的虚拟点，也不是三板预测模型中“看起来最靠近准星”的板。弹道俯仰补偿、`outpost_yaw_offset`、人工 yaw/pitch 偏置和下位机控制不会改变这个物理板框；这些因素通过命令和云台反馈单独检查。

可视化含义必须分开：

- 当前整车模型：Tracker 当前状态推导出的全部装甲板，只用于检查建模。
- 未来整车模型：预测时刻的全部候选板，只用于检查相位和运动预测。
- 洋红色选中框：Solver 迟滞和选板逻辑最终提交的单块击打板，是检查“到底选了哪块板”的权威结果。
- 弹道轨迹/命令角：检查弹道与补偿，不代表物理装甲板的位置。

当目标无效、求解失败或 Solver 进入 `TRACKING_CENTER` 时，选中板有效标志会清除，不保留上一帧洋红色框。可视化开关只影响调试显示，不改变跟踪、选板、开火建议或控制命令。

洋红色框标签现在显示 `SEL P0`、`SEL P1` 或 `SEL P2`，编号就是 Solver 最终提交的相位槽，不是当前检测框编号。debug 日志同步输出：

```text
[Outpost][SELECT] mode=ROTATING selected=... observed=... changed=...
                  fresh=... unseen=... phase=... model_ok=...
                  fire=... diff=... cmd=(yaw,pitch)
```

`selected` 是实际击打槽，`observed` 是最近真实观测关联槽；短暂切板丢帧期间两者可以不同。`changed=1` 表示本帧真正提交了切板，`fresh/model_ok/fire` 分别说明观测新鲜度、模型门和最终开火建议。

## 13. 实车圆心鲁棒拟合

旧版 COLLECTING 并没有真正拟合圆，而是逐帧计算 `armor - R * normal(yaw)`，再用 `alpha=0.5` 更新圆心。这使圆心主要取决于最后几帧 PnP yaw。实车日志中，轨迹点本身可拟合为半径约 `0.246 m` 的圆，但旧模型圆心持续偏离数据圆心 `0.22~0.34 m`，导致观测半径周期性落到 `0.02 m` 或升到 `0.50 m`，最终触发径向异常复位。

第一次实车修正把旧 yaw 低通替换成已知物理半径圆拟合，但新日志显示连续几次局部拟合虽然残差都很小，圆心仍相差约 `0.35 m`，对应自由半径约 `0.184~0.256 m`。根因是短局部圆弧存在多个低残差圆；同时强迫 PnP 轨迹使用物理半径 `0.275 m` 会把 PnP 尺度误差转化为圆心偏移。

当前实现直接对 COLLECTING 阶段的 `(x,y)` 轨迹做鲁棒自由半径圆拟合：

1. 静止判断仍从 `0.4 s` 开始，避免把静止前哨送入旋转模型。
2. 旋转模型至少连续收集 `1.20 s` 和 12 个观测。前哨约 `2.5 s` 一圈，因此数据窗接近半圈。
3. 先用代数圆初始化，再同时优化圆心和观测自由半径；物理半径 `0.275 m` 只用于最终三板预测。
4. 轨迹跨度至少 `0.30 m` 且 `span/fit_R >= 1.70`。使用归一化覆盖率是为了避免 `fit_R≈0.22 m` 时被固定 `0.45 m` 门槛错误拒绝。
5. 自由半径必须位于 `[0.15,0.36] m`；自由圆残差中位数必须不大于 `0.06 m`，P80 不大于 `0.10 m`。
6. 一次合格拟合不能立即建模。至少再观察 `0.25 s`，圆心漂移不超过 `0.05 m`、半径漂移不超过 `0.03 m` 才确认。
7. 用最终圆心重新计算整段轨迹角增量，消除三板切换的 `120 deg` 跳变后再确定旋转方向。
8. 质量不满足、拟合仍漂移或观测断流时保持/返回 COLLECTING，不发布有效 Target、不切板、不开火。

成功日志：

```text
[Outpost] CALIBRATING cx=(...) omega=... fit_R=... med=... p80=... span=... coverage=... n=... confirm=... shift=(...,...)
```

相关诊断均为 debug 级别：`[FIT_WAIT]` 表示数据或质量不足，`[FIT_CANDIDATE]` 表示开始稳定性确认，`[FIT_RESTART]` 表示候选圆心/半径仍在漂移。`CALIBRATING` 和 `ACTIVE` 保持 info 级别。

离线数值回归使用半径 `0.222 m`、接近半圈的带噪轨迹：跨度 `0.444 m`，旧 `0.45 m` 固定门槛会误拒；新门槛得到 `coverage=1.99` 并通过。另一段只有 `70 deg` 的短弧因覆盖率不足被拒绝。实车是否停止反复重建仍必须由下一轮真实日志确认。

运行期径向残差超过 `0.20 m` 时只拒绝当前PnP观测，不再销毁已经完成的长期模型。日志证明实车PnP会在特定视角周期性给出 `rho≈0.05 m` 或 `rho≈0.50 m`，这些坏观测可以持续约 `0.15 s`，但中间模型和预测仍保持正确。被拒绝观测不会刷新开火新鲜度；最后接受观测超过 `0.15 s` 后自动关闭开火，重新出现合格观测后恢复。真正离开前哨仍由 Tracker 的 `1.0 s` 丢失超时复位整次模型。

## 14. 长期建模与短期预测

前哨链路必须把结构参数和瞬时状态分开：

- 长期层：在本次攻击窗口内，连续轨迹估计圆心、观测轨迹半径和旋转方向；三个相位槽分别累计自己的高度。这些量不能由最新一帧 PnP 直接改写。
- 短期层：最新一帧被接受的装甲板位置锚定当前板号和相位；按固定 `±2.513 rad/s` 传播到当前时刻，再按弹丸飞行时间和控制延迟预测击打相位。
- 新鲜度层：切板时允许在无观测的短时间内继续传播并开火，最长为 `0.15 s`。超过后开火门关闭，但模型相位仍可按固定角速度传播至 `1.0 s`，避免径向坏观测期间预测框冻结后再跳变；超过 Tracker 的 `1.0 s` 丢失时间后整次前哨模型复位。

这能同时避免两类错误：短期 PnP 噪声拖动长期圆心，以及长期平均模型忽略目标当前已经转到哪里。

当前 `xyz_in_world` 只通过 IMU 旋转消除云台姿态，没有叠加车体平移里程计。本项目的比赛假设是攻击前哨期间机器人静止，因此本次攻击窗口内可以累计模型；切走目标后不保存圆心、板序或相位，下次攻击重新收集和拟合。攻击窗口可以短于一圈，也可以持续很久，窗口长度不是状态切换条件；未观察到三个高度槽时始终禁止旋转模型开火。
