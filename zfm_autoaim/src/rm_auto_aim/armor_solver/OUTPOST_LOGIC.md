# 前哨站逻辑说明

这份说明对应当前 `zfm_autoaim` 的前哨站实现。

## 核心规则

1. 先建模，再预测。
2. 有可靠观测时，用观测修正模型，并锁定当前观测板。
3. 暂时看不到可靠观测时，直接用模型和上一块观测板外推。
4. 如果连续 `1.0s` 没有“可用观测”，销毁模型，下一次重新收集。

## 状态机

- `COLLECTING`
  - 收集轨迹，拟合旋转圆心和角速度。
  - 还没有 Z 轴三板标定前，不参与正常开火。
- `CALIBRATING`
  - 已经拟合出圆，但 Z 轴槽位还在补全。
  - 继续用观测修正相位和槽位。
- `ACTIVE`
  - 三块板的相位和高度都标定完成。
  - 看得到时用观测修正，看不到时用模型外推。
- `STATIC`
  - 目标基本不动，按静态目标处理。

## 观测处理

- 当前观测有效时：
  - 用观测板位修正模型。
  - 记录 `last_seen_time`。
  - 更新当前板位和相位残差。
  - 发布 `outpost_has_observed_z=true` 和 `outpost_observed_z`，Solver 选中当前观测板时用它修正击打高度。
- 当前观测无效时：
  - 只拒收，不销毁模型。
  - 继续保留上一次的模型状态，等待下一帧恢复。
  - `outpost_has_observed_z=false`，Solver 使用三板模型高度外推。

## 选板逻辑

- 普通目标逻辑不变。
- 前哨站只按相位槽位选板，不再用“中间层/高低层”去强行重排物理顺序。
- 有可靠观测时，Solver 选择 `outpost_observed_plate`，并清空候选切板计时。
- 短暂无可靠观测时，只在上一块观测板和旋转顺序的下一块板之间比较；这时才允许提前选择下一块板。
- 可靠观测恢复后，选板必须回到当前观测关联板，提前切板逻辑不能在“刚出现”的帧继续触发。
- 开火仍要求：
  - 观测新鲜
  - 相位误差在阈值内
  - 云台本身对准

## 可视化

前哨站 RViz 只保留：

- `raw_meas`：当前真实观测到的板子
- `selected_aim`：最终选中的击打框
- `selected_aim_label`：击打板号

不再绘制：

- 拟合圆
- 圆心
- 旋转箭头
- 未来三板预测点
- 当前三板模型点

## 关键参数

- `solver.outpost_max_unseen_time = 0.15`
  - 这是开火新鲜度阈值，不是模型销毁阈值。
- `1.0s` 未见可用观测
  - 销毁前哨站模型，重新收集。
- `solver.outpost_max_phase_error = 15deg`
  - 开火阶段允许的相位误差。
