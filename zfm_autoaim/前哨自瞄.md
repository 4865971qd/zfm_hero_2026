# zfm_autoaim 前哨自瞄说明

本文只描述 `zfm_autoaim` ROS2 工作空间中的前哨站链路。它和纯 C++ `autoaim` 项目逻辑保持一致，但代码、消息、时间和调试方式完全独立，不共享实现。

## 1. 相关包和源码

| 文件/包 | 职责 |
|---|---|
| `rm_auto_aim/armor_detector` | 灯条检测、数字分类、IPPE PnP、可选 BA |
| `armor_detector/src/armor_pose_estimator.cpp` | PnP 双解选择、位姿有效性检查 |
| `armor_solver/src/armor_tracker.cpp` | 前哨模式识别、观测输入和 Tracker 状态机 |
| `armor_solver/include/armor_solver/motion_model.hpp` | `OutpostTracker` 圆模型、Z 标定和相位关联 |
| `armor_solver/src/armor_solver_node.cpp` | TF 变换、Target 消息发布、定时解算和 RViz marker |
| `armor_solver/src/armor_solver.cpp` | 飞行时间预测、迟滞选板、弹道和开火门控 |
| `rm_interfaces/msg/Target.msg` | 前哨模型在节点之间传递的字段 |
| `rm_bringup/config/node_params/armor_solver_params.yaml` | 当前运行参数 |

## 2. ROS2 数据流

```text
sensor_msgs/Image
  -> armor_detector
  -> rm_interfaces/Armors（相机时间戳、相机坐标系）
  -> tf2_filter / TF 变换到 target_frame，默认 odom
  -> Tracker / OutpostTracker
  -> rm_interfaces/Target
  -> 4 ms timerCallback
  -> Solver::solve
  -> rm_interfaces/GimbalCmd
  -> 串口节点 / 下位机
```

前哨链路的入口条件是 `Armor.number == "outpost"`。分类字符串、大小写和标签文件必须完全一致。

## 3. 时间和坐标系约束

### 3.1 时间

OutpostTracker 使用 `Armors.header.stamp` 转换出的秒值记录观测时间；Solver 使用节点 ROS 时钟的 `current_time.seconds()` 判断新鲜度。

必须保证：

- 图像消息时间戳和节点时钟属于同一个 ROS clock domain。
- 使用仿真时间时，相关节点统一设置 `use_sim_time`。
- 时间戳单调递增，不能一部分使用系统时间、一部分使用仿真时间。
- `Target.header.stamp` 保留原始观测时间，不能在中间节点改成发布时间。

时间域不一致的典型症状是 `outpost_last_seen_time` 看似正常，但 Solver 计算的 unseen time 为负数或极大值，最终一直不开火。

### 3.2 坐标系

ArmorSolverNode 会先把每块装甲板位姿转换到 `target_frame`，默认 `odom`。圆心、Z 高度和 yaw 都在该坐标系下建模。

Solver 查询云台 TF，计算枪口在 `target_frame` 下的位置，再把预测目标转换成枪口相对坐标。以下内容不能混用：

- 相机坐标系 PnP 平移。
- 云台坐标系外参。
- `odom`/惯性系目标状态。
- 枪口相对坐标下的最终瞄准点。

如果 TF 轴方向或时间不同步，圆心、旋转方向、pitch 和弹道都会同时异常。

## 4. 模型假设和固定常量

当前前哨模型使用固定规则参数：

| 常量 | 当前值 | 作用 |
|---|---:|---|
| 固定旋转半径 | 0.275 m | 反推圆心和预测板位 |
| 固定角速度绝对值 | 2.513 rad/s | 收集阶段只估计正反方向 |
| 最短收集时间 | 0.4 s | 防止少量观测直接建模 |
| 最少收集观测 | 3 次 | 与时间条件同时满足 |
| 静止位移阈值 | 0.05 m | 收集窗口首尾位移小于该值进入 STATIC |
| Z 初始间隔 | 0.10 m | 初始化三块板的高度槽 |
| Z 标定匹配阈值 | 0.05 m | 判断高度槽是否被观测命中 |
| Z 切板阈值 | 0.06 m | 建立尚未观测到的高度槽 |
| Z 学习率 | 0.05 | 每块物理板独立更新高度 |
| 最大模型相位外推 | 1.0 s | 覆盖正常切板不可见窗口；开火新鲜度仍由 `solver.outpost_max_unseen_time` 限制 |
| 径向残差阈值 | 0.20 m | 拒绝不符合圆模型的观测 |
| 最大板关联误差 | 55 deg | 三板相位关联上限 |
| 单次最大相位修正 | 15 deg | 限制单帧观测对模型的拖动 |
| 离群持续复位时间 | 0.15 s | 连续异常后重新 COLLECTING |

这些常量定义在 `motion_model.hpp`，目前不是 ROS 参数。修改 YAML 不会改变它们。

## 5. OutpostTracker 状态机

```text
                  旋转目标
COLLECTING ----------------------> CALIBRATING
    |                                  |
    | 位移不足 0.05 m                  | 三个高度槽全部观测到
    v                                  v
 STATIC                              ACTIVE

ACTIVE/CALIBRATING -- 连续径向或相位离群 0.15 s --> COLLECTING
ACTIVE/STATIC -- 无观测超过 1.0 s --> Tracker LOST
```

### 5.1 COLLECTING

圆心由当前板位置和 PnP yaw 反推：

```text
cx = x - 0.275 * cos(yaw)
cy = y - 0.275 * sin(yaw)
```

圆心使用 `0.5` 低通更新。累计相位变化只决定角速度正负号，角速度绝对值固定为 2.513 rad/s。

至少 3 次观测且持续 0.4 秒后才进行静止/旋转判断。COLLECTING 期间 ArmorSolverNode 发布 `tracking=false`，定时器不会把模型当成有效瞄准目标。

### 5.2 CALIBRATING

旋转方向确定后，建立 `z-0.1`、`z`、`z+0.1` 三个高度槽。观测会更新最近槽；当观测和已有槽相差大于 0.06 m 时，优先填充尚未见过的槽。

三个槽都在正负 0.05 m 范围内被真实观测命中后，按物理板顺序映射：

| 物理板索引 | 高度 |
|---:|---|
| 0 | 最高 |
| 1 | 最低 |
| 2 | 中间 |

高度和相位偏移必须一起重排。完成后设置 `outpost_z_calibrated=true`，状态进入 ACTIVE。

CALIBRATING 期间仍发布 `tracking=false`，不切板、不输出开火建议。

### 5.3 ACTIVE

ACTIVE 中，观测板号主要通过相位关联确定：

1. 检查实际半径与 0.275 m 的差。
2. 预测三块物理板在当前时间的相位。
3. 选择与观测相位误差最小的板。
4. 最小误差超过 55 deg 时拒绝观测。
5. 接受观测时，单次相位修正限制在正负 15 deg。
6. 只更新关联到的物理板高度。

最近观测后的模型相位最多外推 1.0 秒，覆盖正常切板不可见窗口；开火仍由 `solver.outpost_max_unseen_time` 的 0.15 秒新鲜度独立限制。

### 5.4 STATIC

收集窗口内平面位移不足 0.05 m 时进入 STATIC。位置按 `0.3` 系数平滑。

STATIC 可用于显示和瞄准中心，但不会伪造旋转三板 Z 标定；`outpost_z_calibrated` 仍为 false，因此不会给出开火建议。

## 6. Target 消息映射

前哨 ACTIVE 时 `rm_interfaces/msg/Target` 主要字段如下：

| 字段 | 含义 |
|---|---|
| `tracking` | Tracker 是否已进入 TRACKING/TEMP_LOST |
| `id` | 必须为 `outpost` |
| `armors_num` | 必须为 3 |
| `position` | plate 0 高度对应的圆心位置 `(cx, cy, z0)` |
| `yaw` | plate 0 当前相位 |
| `v_yaw` | 固定规则角速度，带方向符号 |
| `radius_1` | 固定半径 0.275 m |
| `d_zc` | `z1-z0` |
| `d_za` | `z2-z0` |
| `outpost_angle_offsets` | 三块物理板相对参考板的相位偏移 |
| `outpost_observed_plate` | 最近观测关联到的物理板索引 |
| `outpost_has_observed_z` | 当前帧是否有被 OutpostTracker 接受的可靠真实观测高度 |
| `outpost_observed_z` | 当前可靠观测板的真实高度，选中观测板时用于修正击打 Z 和 RViz 选中框高度 |
| `outpost_z_calibrated` | 是否完成三板物理高度标定 |
| `outpost_last_seen_time` | 最近真实观测时间 |
| `outpost_phase_error` | 最近相位观测残差 |

前哨板位公式为：

```text
p_i = center + [R*cos(angle_i), R*sin(angle_i), z_offset_i]
```

普通四装甲板使用中心减半径方向。修改 `getArmorPositions()` 时必须保留这个差异。

### 6.1 消息重新生成

`Target.msg` 已增加 `normal_last_seen_time`，同时包含 `outpost_has_observed_z`、`outpost_observed_z` 等前哨字段。任何消息定义修改后都必须重新生成 `rm_interfaces`。

如果编译报错提示 `Target` 没有某个字段，通常是旧的 `build/`、`install/` 或已 source 的旧工作空间覆盖了新消息头。应清理旧生成物，并从 `rm_interfaces` 开始重新构建。

## 7. Solver 预测和选板

Solver 的预测时间为：

```text
observation_delay + flying_time + prediction_delay
```

其中 `observation_delay` 来自当前 ROS 时间减去 `Target.header.stamp`。目标中心和 yaw 都先预测到弹丸到达时间。

第一次选板后，Solver 使用选中板的飞行时间精炼。如果精炼前后时间差超过 3 ms，会重新计算板位和选板。

旋转前哨的到达火线：

```text
cam_dir = atan2(-center_y, -center_x)
arrival_cam_dir = cam_dir - omega * flying_time
```

旋转前哨选板和 `autoaim` 保持一致，核心是“可靠观测锁当前板，短间隙才外推”：

1. 当前帧存在可靠真实观测时，Solver 直接选择 `outpost_observed_plate`，并清空 pending 切板状态；看得到哪块，就按模型和弹道预测这块板的击打位置。
2. 当前帧没有可靠真实观测、但模型仍未超过 1.0 s 销毁窗口时，只比较上一块观测板和按旋转顺序即将出现的下一块板。
3. 只有第 2 种短暂无可靠观测间隙，才允许提前切到下一块板，用来补偿云台响应和弹丸飞行时间。
4. 可靠观测恢复后，选板必须回到当前观测关联板，不允许“刚看到最高板却被提前切换逻辑拉成中间板”。

无可靠观测分支中的候选板仍按火线窗口、接近方向和迟滞提交。切板迟滞参数写在 Solver 源码中：

| 条件 | 当前值 |
|---|---:|
| 候选板至少优于当前板 | 22 deg |
| 当前板保持窗口 | 55 deg |
| 强制切板角差 | 88 deg |
| 普通切板确认时间 | 0.090 s |
| 两次切板最小间隔 | 0.160 s |

每块物理板有独立的 Z 平滑状态，更新系数为 0.3。最终选中板等于当前可靠观测板时，击打 Z 优先使用 `outpost_observed_z` 修正模型高度；短暂看不到或提前选择下一板时，使用已标定三板模型高度外推。离开前哨模式或目标失效时，选板索引、候选计时和三块板的平滑状态会复位。

最终超前相位：

```text
lead = omega * (flying_time + prediction_delay)
       - sign(omega) * outpost_yaw_offset
```

`controller_delay` 当前只用于普通目标；前哨已有单独的飞行时间和相位超前链路，不能再重复叠加同一延迟。

## 8. 开火门控

旋转前哨 `fire_advice=true` 必须同时满足：

1. `outpost_z_calibrated=true`。
2. 最近真实观测时间有效。
3. unseen time 位于 `[-0.02, outpost_max_unseen_time]`。
4. `abs(outpost_phase_error) <= outpost_max_phase_error`。
5. 选中板到到达火线的角差小于 30 deg。
6. 选中板正在接近火线：`v_yaw * angle_diff < 0`。
7. 云台当前 yaw/pitch 已进入物理射击窗口。

如果 Solver 实际运行在 `TRACKING_CENTER` 分支，该分支会强制关闭开火。当前默认前哨角速度 2.513 rad/s，远低于默认中心切换阈值 60 rad/s，正常情况下不会触发该模式。

当前 YAML：

```yaml
solver:
  prediction_delay: -0.005
  outpost_yaw_offset: 0.0
  outpost_max_unseen_time: 0.15
  outpost_max_phase_error: 15.0
  shooting_range_width: 0.135
  shooting_range_height: 0.135
  bullet_speed: 11.6
```

Solver 参数在节点创建时读取并缓存。修改 YAML 后需要重启 `armor_solver`，不是保存文件后立即生效。

## 9. 丢失、复位和节点行为

- COLLECTING/CALIBRATING：Tracker 状态保持 DETECTING，Target `tracking=false`。
- ACTIVE/STATIC：连续两个更新周期后 Tracker 进入 TRACKING。
- 一次未观测到 `outpost`：进入 TEMP_LOST。
- TEMP_LOST 中重新观测：恢复 TRACKING。
- 距最后观测超过 1.0 秒：销毁 OutpostTracker，回到 LOST，下次重新建模。
- `timerCallback` 在 Target tracking 时调用 Solver。普通目标会在定时器入口做瞄准新鲜度拦截；前哨可以继续输出有限外推的瞄准命令，但 Solver 会用 Z 标定、相位残差和观测新鲜度关闭开火。
- 目标无效或解算异常时，发布 `fire_advice=false` 和零偏差安全命令，并复位 Solver 状态。

## 10. 调试入口

将 `armor_solver_params.yaml` 中的 `debug` 设为 true 后，可使用：

| 入口 | 内容 |
|---|---|
| `armor_solver/target` | 圆心、yaw、角速度、Z 偏移、标定和新鲜度字段 |
| `armor_solver/cmd_gimbal` | yaw/pitch、差值、距离和 `fire_advice` |
| `armor_solver/marker` | 圆、三块当前板、飞行时间后预测板、选中板和弹道 |
| `[Outpost] AIM` | 选中板、三板到火线角差、lead、yaw/pitch |
| `[Outpost] STATUS` | 中心、角速度、板高和飞行时间 |

## 11. 最容易出错的地方

### 11.1 标签或装甲类型不正确

症状：能检测到板，但 `Target.id` 不是 `outpost`，或一直走普通 EKF。

检查：

- `label.txt` 标签是否准确为小写 `outpost`。
- `classifier_threshold` 是否过高。
- `ignore_classes` 是否误包含前哨标签。
- 当前一致性过滤会拒绝 LARGE 类型的 `outpost`；前哨应按小装甲板 PnP 模型识别。

### 11.2 TF 或时间域错误

症状：圆心漂移、相位方向错误、unseen time 异常、始终不开火。

检查：

- `Armors.header.frame_id` 是否正确。
- 相机到云台、云台到 `odom` 的 TF 方向是否正确。
- TF 时间是否能覆盖图像时间戳。
- 所有节点是否统一使用系统时间或 `use_sim_time`。
- 是否 source 了另一个工作空间中的旧 TF/消息包。

### 11.3 PnP 双解切换

前哨顶部或大倾角区域最容易出现 IPPE 双解竞争。当前实现先比较重投影误差；误差接近时再按 roll 和灯条倾斜方向消歧。

如果最高板持续抖：

- 观察 `armor_detector` 的原始角点和 PnP marker。
- 检查顶部区域畸变、曝光和灯条完整性。
- 暂时关闭 BA 对比，确认是 PnP 双解还是 BA 引入的 yaw 变化。
- 不要先调前哨相位参数，因为错误位姿会污染圆心、Z 和相位三个层面。

### 11.4 Z 标定无法完成

常见原因：

- 第三块板一直被遮挡，没有真实命中三个高度槽。
- PnP Z 噪声超过 0.05~0.06 m。
- TF 的 pitch/roll 误差让 Z 随旋转角周期变化。
- 实际板高差和正负 0.1 m 初始化假设差异过大。

不要通过发布假的 `outpost_z_calibrated=true` 绕过。这样会把未初始化的高度和板号直接送入选板与开火。

### 11.5 物理板号和画面位置混淆

plate 0/1/2 是标定后的物理板索引，不是“当前画面最上/左/右板”。物理映射是最高、最低、中间三个高度，并带各自相位偏移。

排查时要区分：

- 同一个物理板号总抖：该板观测或高度状态有问题。
- 每次转到画面顶部都抖：图像区域、角点或 PnP 视角问题。
- 物理板号在顶部附近互换：相位关联或 Z 聚类问题。

### 11.6 相位预测飞走

检查：

- `v_yaw` 正负是否与 RViz 旋转方向一致。
- `Target.header.stamp` 和 `current_time` 是否同一时钟。
- `bullet_speed` 是否为 m/s。
- `outpost_phase_error` 是否频繁接近 55 deg。
- 相机帧是否长时间断流；观测相位只允许最多 0.15 秒外推。

### 11.7 切板瞬间跳变

- 高度和相位偏移必须成对重排。
- 三块板必须分别保存 Z 平滑状态。
- 不要移除 22/55/88 deg 和 0.09/0.16 s 的迟滞。
- 目标失效、切换模式时必须复位 `aim_idx_` 和 pending switch 状态。
- RViz 中确认跳的是模型板号还是只有云台输出；后者还需检查弹道和手动补偿。

### 11.8 一直不开火

按顺序检查：

1. `Target.tracking` 是否为 true。
2. `Target.id` 是否为 `outpost`。
3. `armors_num` 是否为 3。
4. `outpost_z_calibrated` 是否为 true。
5. `now - outpost_last_seen_time` 是否小于 0.15 s。
6. `abs(outpost_phase_error)` 是否小于 15 deg。
7. `[Outpost] FIRE` 中 diff 是否小于 30 deg、app 是否为 true。
8. `yaw_diff/pitch_diff` 是否进入射击窗口。
9. 串口节点和下位机是否实际使用 `fire_advice`。

### 11.9 参数修改没有生效

- Solver 参数只在节点创建时读取，修改 YAML 后必须重启节点。
- 确认 launch 实际加载的是 `src/rm_bringup/config/node_params/armor_solver_params.yaml`，而不是旧 `install/` 中的副本。
- 使用 `ros2 param get` 检查运行节点的最终参数值。
- 修改 `Target.msg` 后要清理旧消息生成物并重新构建。

### 11.10 debug 关闭后看不到模型

`debug=false` 会关闭 RViz marker、PlotJuggler 和高频 Solver 日志，但不影响实际跟踪和命令输出。判断算法是否运行，应同时检查 `armor_solver/target` 和 `armor_solver/cmd_gimbal`，不能只看 marker。

### 11.11 低帧率

收集时间、离群持续时间、失效时间、选板确认和开火新鲜度均按秒计算。低帧率会减少观测密度，但不会改变这些阈值对应的物理时间。

ACTIVE/STATIC 到 Tracker TRACKING 有两个更新周期的交接确认。真正允许开火仍由 Z 标定、真实观测新鲜度、相位误差和火线窗口共同决定。

### 11.12 两个项目只修改了一个

`autoaim` 和 `zfm_autoaim` 只有算法思路一致，没有共享代码。修改固定半径、角速度、Z 阈值、相位关联、选板迟滞或开火窗口时，必须在两个项目分别修改、分别记录和分别验证。

## 12. 推荐测试流程

1. **检测阶段**：查看 `armor_detector/result_img`，确认分类、角点和 PnP 稳定。
2. **TF 阶段**：检查转换到 `odom` 后的单板轨迹和 Z，不启动开火。
3. **建模阶段**：观察 COLLECTING、CALIBRATING、ACTIVE 状态和圆心。
4. **板号阶段**：确认物理板号稳定，三块板高度趋势合理。
5. **预测阶段**：检查 `plates_now` 和 `strike_pred` 的方向、提前量和连续性。
6. **选板阶段**：确认迟滞生效，不在相邻板之间快速来回切换。
7. **命令阶段**：检查 yaw/pitch、弹道和手动补偿，不开弹丸。
8. **开火阶段**：最后检查新鲜度、相位、火线窗口、云台窗口和下位机执行。

每次测试只改变一个参数，并保留 rosbag、日志、参数快照和 RViz 录屏。先证明模型正确，再讨论命中率。

## 13. 2026-07-19 仿真验证修正

以下两项与 `autoaim` 保持行为一致，但在本项目内独立实现，不共享代码：

1. **异常观测必须由连续的真实测量累计**：`outlier_start_t_` 不得跨越没有调用 `addMeasurement()` 的时段继续计时。新测量与上一测量的间隔超过 `max_outlier_duration_` 时，旧异常段先清零；重捕获后的第一个坏测量只开始新的异常段。Tracker 的 lost/unseen 状态机继续单独负责真正的目标丢失。
2. **切板提交必须同时满足观测新鲜和相位有效**：88 度强制切板只绕过时间迟滞，不能绕过 `outpost_max_phase_error`。坏相位帧允许保留候选板，但重启 pending 确认时间且禁止修改 `aim_idx_`；相位恢复后才允许提交。

`autoaim_1` 仿真中，`29~38 deg` 的坏相位候选切板全部被拦截，三次实际切板相位约为 `1.7 deg`、`2.6 deg` 和 `0 deg`。异常观测跨长断流后的首次重捕获不再让模型退出 `ACTIVE`。

仿真最高板的算法命令稳定：求解 pitch 为 `14.30~14.39 deg`，最终命令固定 `14.32 deg`；持续视觉抖动来自 Gestalt 云台反馈未跟随命令，不能把该游戏现象转化为 ROS2 实车算法的额外平滑或补偿。

## 14. RViz 真实选板可视化

RViz marker 现在在 `timerCallback()` 完成真实 `Solver::solve()` 之后发布，不再由图像回调拿空的 `GimbalCmd` 提前构造。发布频率限制在约 30 Hz，并且只在 `debug=true` 时启用；这不会改变 250 Hz 控制求解和命令发布。

前哨可视化分为三个不同层次：

| Marker namespace | 含义 | 是否是最终选板 |
|---|---|---|
| `plates_now` | 当前观测时间的三板模型 | 否 |
| `model_future` | 使用本次 Solver 预测时间跨度得到的三板未来模型 | 否，只用于检查预测方向和相位 |
| `selected_aim` | Solver 本次真实提交的击打板，洋红色实体板框 | 是 |
| `selected_aim_label` | 显示 `AIM P0/P1/P2` 的物理板号 | 是 |
| `trajectory` | `gimbal_link` 中的弹道轨迹 | 否 |

`selected_aim` 的数据源是 Solver 内部只读快照。前哨求解先完成目标时间外推、候选板比较、`aim_idx_` 迟滞/强制切板门控、每板独立 Z 和相位超前，然后把最终 `aim_point`、`aim_angle` 和物理板号保存到快照。节点只负责把这个结果画出来，不再用命令 yaw/pitch 和距离反算装甲板。

可靠观测存在时，`selected_aim` 应该对应当前 `outpost_observed_plate`；只有短暂无可靠观测的切板间隙，`selected_aim` 才可能提前显示下一块板。若刚重新看到板的瞬间仍跳到其他槽位，优先检查 `outpost_has_observed_z` 是否正确发布。

该板框表示弹道俯仰补偿和人工角度偏置之前的物理击打板位置。这样可以直接判断建模、预测和选板是否正确；弹道补偿是否正确看 `trajectory` 与命令，云台是否跟随则看串口反馈，三者不能混为一个标记。

三条高度圆现在严格对应：

```text
plate 0: position.z
plate 1: position.z + d_zc
plate 2: position.z + d_za
```

每次发布前会先 DELETE 条件性前哨 marker，再追加本帧仍有效的 marker。切换普通目标/前哨、失去目标、求解失败或进入中心跟踪时，旧的 `selected_aim`、未来模型、状态文字和高度圆不会残留。旧版 `strike_pred` 也会被显式删除，防止 RViz 中留下历史点。

实车检查选板时以洋红色 `selected_aim` 和 `AIM Pn` 为准：

1. 板号不变但框连续抖动：检查该物理板的 Z、相位预测和 PnP 输入。
2. `AIM Pn` 在相邻板间快速变化：检查相位新鲜度、22/55/88 度阈值和 0.09/0.16 秒迟滞。
3. `model_future` 正确但 `selected_aim` 选错：问题位于候选比较或切板提交。
4. `selected_aim` 稳定但云台抖动：问题位于弹道、角度补偿、串口或下位机执行，不应修改前哨建模。
5. 没有 `selected_aim`：先检查 `Target.tracking`、Solver 是否成功返回、是否处于 `TRACKING_CENTER`，以及 `debug` 是否开启。

## 15. 实车圆心鲁棒拟合

旧版 `OutpostTracker` 在 COLLECTING 中使用单帧 PnP yaw 计算候选圆心，并以 `alpha=0.5` 更新。它不是轨迹圆拟合，最后几帧的 yaw 系统误差会直接固化为圆心偏差。实车 `autoaim` 日志证明，旧圆心相对轨迹拟合圆心偏离 `0.22~0.34 m`，足以让固定半径残差在旋转周期内反复越过复位阈值。相同缺陷存在于本项目的独立实现中，因此同步修正算法行为，但不共享源码。

当前 ROS2 实现：

- 至少收集 `0.65 s`、12 个 `(x,y)` 观测，轨迹跨度至少 `0.30 m`。
- 先做代数圆初始化，再以固定物理半径 `0.275 m` 做 Huber 鲁棒圆心优化。
- 自由拟合半径限制为 `[0.18, 0.36] m`。
- 固定半径残差中位数上限 `0.08 m`，P80 上限 `0.13 m`。
- 拟合成功后，使用新圆心重算整段角度增量；相邻观测按 `120 deg` 板间距去除切板跳变，再确定 `omega` 正负。
- 拟合失败或方向不明确时保持 COLLECTING，Target 不进入 tracking，Solver 不会选板或开火。
- ACTIVE 阶段圆心保持锁定，仍用原有 `0.20 m / 0.15 s` 连续径向异常保护检测真实模型失效。

成功时输出：

```text
[Outpost] CALIBRATING cx=(...) omega=... fit_R=... med=... p80=... span=... n=...
```

`[Outpost][FIT_WAIT]` 只受 debug 日志等级控制。排查时先看 `fit_R/med/p80/span`，不要先调大运行期径向阈值。
